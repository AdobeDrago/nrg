DA in five minutes

DA (Document Authoring, at da.live) is where the site's content lives. It looks like a file browser with folders, documents and spreadsheets. Each document becomes one page of the website, and its location becomes the page address: the document en/providers/reliant is the page /en/providers/reliant.

  • Documents are pages. You edit them like a word-processor file.
  • Sheets are spreadsheets that feed data to the site. The plans sheet is one of them.
  • Blocks are the designed parts of a page, such as a hero or a row of cards. In a document a block looks like a table: the shaded top row holds the block's name, and the rows below hold its content. Keep the name row exactly as it is; it tells the site how to display the content.
  • Sections are separated by a horizontal line (---). Each section is a band on the page.

Preview and Publish

Saving in DA happens automatically, but nothing changes on the website until you use the Preview and Publish buttons at the top right of the editor.

  • Preview updates the private test site, main--nrg--adobedrago.aem.page. Only people with the link see it. Use it to check your work.
  • Publish updates the live site, main--nrg--adobedrago.aem.live, which visitors see.

Always preview first, check the page, then publish.

What to gather first

Collect these before you start. Having them ready makes the rest of the guide mostly copy and paste.

  • Provider name, written exactly as the brand writes it (for example Green Mountain Energy).
  • Page name for the address: short, lower case, words joined with hyphens (for example green-mountain). It becomes /en/providers/green-mountain, so choose it carefully; changing it later breaks links.
  • Logo as a PNG with a transparent background, at least 520 pixels wide.
  • Hero image for the top of the provider page (the existing pages use the logo on a soft background, about 1000 × 550 pixels).
  • Page copy: a short introduction, three to six benefits or features (a title and a paragraph each), and contact details with a phone number and opening hours.
  • Plan details for every plan: name, term, price per kWh, the estimated monthly bill at 1,000 kWh, renewable percentage, a one-line highlight, and links to the Electricity Facts Label (EFL) and to enrollment.
  • Where the plans are sold: all of Texas, certain utility areas (such as Oncor or CenterPoint), or a list of ZIP codes.
  • Spanish translations of the page copy and plan text, if the provider will also appear on the Spanish site.
1

Ask a developer to register the brand

Who: a developer · When: first, because it takes a code release

Do this before anything else

The plan cards in ZIP search results only know the five current providers (Reliant, Cirro Energy, Discount Power, Green Mountain Energy and Direct Energy). A new provider's plans will still appear, but without its logo and without the customer-service line until a developer adds the brand to the site's code.

Send the developer:

  • the provider name as it should appear on the cards;
  • a two-letter brand code you'll use in the sheet (the current ones are RE, CE, PW, GM and DE), for example XE;
  • the customer-service hours to show on each card, for example Weekdays, 8 a.m. – 5 p.m. CST.

For the developer: add an entry to BRANDS in blocks/plan-cards/plan-cards.js (name, hours, and a name pattern), then merge to main. All cards share one phone number, BRAND_PHONE.

You can carry on with steps 2 to 5 while you wait. Just don't publish the plans until the code change is live.

2

Upload the logo

Who: you · Where: the media/providers folder in DA

  1. In DA, open the site's top folder (adobedrago / nrg), then media, then providers.
  2. Rename your logo file to the page name followed by -logo.png, for example green-mountain-logo.png. This matches the five logos already there.
  3. Drag the file from your computer into the DA folder window. It appears in the list once uploaded.
Images inside pages

You don't have to upload other images to a folder first. When you drag an image straight into a document, DA uploads it for you and stores it next to that page.

3

Create the provider page

Who: you · Where: the en/providers folder in DA

The easiest way to get the right layout is to copy an existing provider page and replace its content. Reliant's page is a good starting point because it uses every section.

  1. In DA, open en, then providers. You'll see the five provider documents and index (the Providers landing page).
  2. Click New, choose Document, and give it your page name (for example green-mountain). The new, empty document opens.
  3. In another browser tab, open the reliant document. Click inside it, press Ctrl + A (Cmd + A on a Mac) to select everything, then Ctrl + C to copy.
  4. Go back to your new document, click inside it and press Ctrl + V to paste. All the block tables come across with their layout.
  5. Close the Reliant tab without changing anything.
  6. Now replace Reliant's content with the new provider's, section by section, as shown below.

Preview it

  1. Click Preview at the top right of the editor. The test page opens in a new tab.
  2. Read the whole page. Check the logo, every card, the phone number and the tab title.
  3. Search the page for "Reliant" (Ctrl + F) to catch anything you missed.
4

Add the plans to the sheet

Who: you · Where: en/data/plans

When a shopper enters a ZIP code, the plans page reads this sheet and shows every plan sold at that ZIP. The sheet has two tabs at the bottom:

  • plans: one row per plan. This is where you add the new provider's plans.
  • zips: one row per ZIP code, with its city, state and utility. Leave it alone unless the provider serves a ZIP that isn't listed yet.
  1. Open the plans sheet and click the plans tab.
  2. Go to the first empty row below the existing plans. Add one row per plan; don't leave empty rows between plans.
  3. Fill in the columns as described below. Copying an existing row and editing it is the quickest way to keep the format right.
  4. Don't rename, reorder or delete columns. The site finds each value by its column name.

Preview the sheet and test it

  1. Click Preview at the top right of the sheet.
  2. Open the test plans page with a ZIP where the plans should appear, for example …/en/plans?zip=75001 (Addison, Oncor). Change the five digits at the end to try other ZIPs.
  3. Check each new card: name, price, term, highlight, badge, both links and the filter buttons. Also check a ZIP where the plans should not appear.

Until the developer's change from step 1 is live, the new cards have no logo and no phone line. That's expected.

5

List the provider on the site

Who: you · Where: four kinds of pages

The new page isn't linked from anywhere yet. Add the provider wherever the other providers appear. In each place, copy an existing provider's row or entry and edit it, so the layout stays the same.

Providers landing pageThe Provider List block: one row per provider with the logo on the left, and a description, two bullet points and a "Learn more" link on the right.en/providers/index
Homepage logo stripThe Provider Cards block under "Featured providers": the logo, name, a line of copy and a "View plans" link.en/index
FooterThe "Providers" list. Add a bullet linking the name to the new page.en/footer
Plan card logosThe last row of the Plan Cards block holds only logos. Drag the new logo into that row, next to the others.en/plans · en/personalized/92677
The logo's alt text matters here

On the plans pages, the site matches each logo to its plans by the logo's alt text. Set it to the provider's name, in English, exactly as you gave it to the developer. Right-click the image in DA to edit its alt text.

The site also has a set of pages without en in their address (the top-level index, footer, plans, personalized/92677 and data/plans). If those are still in use, make the same changes there.

Preview each page you changed.

6

Make the Spanish version

Who: you, with the translations · Where: the es folder

The Spanish site is a separate set of documents under es. Repeat steps 3 to 5 there:

  1. Page: in es/providers, create a document with the same page name as the English one (for example green-mountain). Copy in the content of es/providers/reliant and replace it with the translated copy. Change the back link at the top to point to /es/providers/.
  2. Plans: add the same rows to the Spanish sheet, es/data/plans, with the plan text translated and enrollUrl pointing to the /es/… page. Keep the brand code the same.
  3. Listings: update es/providers/index, es/index, es/footer, es/plans and es/personalized/92677.
Keep brand names in English

Logo alt text and the provider name stay in English on Spanish pages. They're brand names, and the plans page matches them in English.

7

Check and publish

Publish in this order, so a visitor never lands on a link to a page that isn't live yet:

  1. Confirm with the developer that the brand change from step 1 is live.
  2. Publish the provider pages (English and Spanish).
  3. Publish the plans sheets (English and Spanish).
  4. Publish the pages that link to the provider: the Providers landing pages, the homepages, the footers and the plans pages.
  5. Open the live site in a private browser window and repeat the checks: the provider page, a ZIP search, the homepage strip and the footer link.

Final checklist

When something looks wrong

The new plans don't show up for a ZIP

Check that the sheet was previewed (or published, for the live site) after your last edit.

Check the zip column. A utility name must be spelled exactly as in the zips tab, and the ZIP itself must be listed in the zips tab, or a TX or utility value won't reach it.

Check that planName isn't empty.

The plan card has no logo or no phone line

Either the developer's change from step 1 isn't live yet, the brand column doesn't match the code you agreed, or the logo is missing from the Plan Cards logo row (or its alt text doesn't match the provider name).

Prices show "cents/kWh" twice, or "$$"

Remove the units and symbols from the sheet cell; enter the number only.

A section of the new page looks unstyled, like a plain table

The block's name row was probably edited or deleted while pasting. Compare it with the same block on Reliant's page and restore the name exactly, for example Provider Hero or Details Cards.

My change is on the test site but not the live site

Preview only updates the test site. Click Publish on that document or sheet. The live site can take a minute to update.

I need to take a provider down

Remove its rows from both plans sheets and its entries from the listing pages, then publish those. Then ask a developer or site admin to unpublish the provider page, so old links don't land on it.
