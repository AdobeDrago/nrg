Everything Energy on Edge Delivery Services

Rebuilding everythingenergy.com — NRG's electricity plan comparison site for Texas and Pennsylvania — on Adobe Edge Delivery Services. Built and hand-polished in 16 commits to match everythingenergy.com's purple/pink brand identity. This is the sales & developer documentation covering what was built, the architecture, the custom blocks, and what's next.

Project overview

This effort recreates Everything Energy — NRG's electricity plan comparison site for Texas and Pennsylvania residents — on Adobe Edge Delivery Services (EDS), authored through Document Authoring (DA). The site lets customers enter their ZIP code, compare plans across five NRG subsidiary providers, and choose a plan — all delivered as EDS blocks on an edge CDN.

Goals

  • Recreate the Everything Energy experience on Edge Delivery Services, authored in DA.
  • Match everythingenergy.com's brand identity — purple/pink colors, Source Sans Pro typeface, pill-shaped ZIP search.
  • Build a ZIP-code-driven plan discovery flow with provider landing pages.
  • Deliver sub-second page loads via edge CDN, replacing the WordPress origin.
  • Enable content authoring without developer involvement — marketing edits in DA.live.

Approach

  • EDS block-based development — every UI module is an authorable block with CSS + JS.
  • Site auto-generated from a brand brief, then hand-polished to match the live site.
  • Content authored in DA.live — Google Docs-like editor, no CMS database.
  • Deployment via git push → AEM Code Sync — push to main auto-deploys to CDN.

Use case & requirements

Use case. NRG operates five retail electricity brands across Texas and Pennsylvania. Their existing WordPress site at everythingenergy.com was slow, hard to update, and couldn't scale content across providers. The site needed to let customers enter their ZIP code, compare plans across all five NRG providers, and choose a plan — with sub-second page loads and content editing that doesn't require a developer.

Plans & providers Complete

The plan discovery flow spans the all-plans page (/plans) and 5 individual provider pages. All use the plan-cards block, which auto-extracts plan data from authored HTML paragraphs.

Plan-cards block

For each plan row, the block JS reads the <h3> (plan name) and <p> elements, then classifies each paragraph by regex pattern matching:

PatternCSS classExample
$, cents, ¢, kWh, rate, price.plan-rate"9.9 cents/kWh" → 36px purple
month, year, term, fixed, variable.plan-term"12-month fixed term" → 14px uppercase
pool, renewable, green, free, night, weekend.plan-tag"Free electricity from 8pm to 6am" → pink pill
Remaining text.plan-desc"Perfect for night owls and EV owners"
First <a> link.plan-button"Choose this plan" → purple CTA
"Best Value" badge. The first plan card in each grid automatically gets a border: 2px solid #7564C1 and a "Best Value" badge positioned at top: -12px via ::before pseudo-element.

EDS architecture

Adobe Experience Manager Edge Delivery Services is a headless CMS + edge-rendered architecture. Content is authored in DA.live, code lives in GitHub, and Adobe's edge CDN fetches, decorates, and serves pages globally.

Content flow

  • Authoring — content editors use DA.live (Google Docs-like) to create and edit HTML pages
  • Code — CSS, JS, and block definitions live in the GitHub repo (AdobeDrago/nrg)
  • Rendering — the edge CDN fetches HTML from GitHub, decorates it with block JS/CSS, serves to browser
  • Deployment — git push main triggers AEM Code Sync (App ID 17488), which deploys CSS/JS/blocks to CDN automatically

Known limitations Review

Accepted for this delivery — each is a candidate for follow-up.

  • Plan data is static
    Plan rates, terms, and features are hardcoded in the HTML pages. No API integration with NRG's plan catalog — content authors must update HTML when plans or rates change.
  • ZIP search is client-side only
    /plans?zip={zip} doesn't filter server-side — all 8 plans are shown regardless of which ZIP is entered. A real plan API would filter by service area.
  • Personalization page is a placeholder
    personalized/92677.html exists with the personalization block styled (gradient background, frosted-glass badges), but no recommendation engine is wired up to generate personalized plan suggestions.
  • No enrollment flow
    "Choose this plan" links to a placeholder (/personalized/92677). Not connected to any provider enrollment API — the final conversion step (enroll in a plan) is not functional.
  • No analytics integration
    delayed.js is a placeholder. EDS core RUM (Real User Monitoring) is active via sampleRUM() beacons to ot.aem.live, but no Adobe Analytics or GA4 is wired up for conversion tracking.
  • Two states only
    Currently serves Texas and Pennsylvania. NRG operates in additional deregulated markets that could be added with new provider pages and ZIP coverage.

Developer notes

Local development

# Prerequisites: Node.js 18+ npm install -g @adobe/aem-cli # Clone and run locally git clone https://github.com/AdobeDrago/nrg.git cd nrg aem up # opens at http://localhost:3000 # Local server proxies content from DA.live and runs block CSS/JS locally. # Edits to CSS/JS hot-reload. Content edits happen in DA.live.

Content authoring

Content is authored in DA.live — not in the GitHub repo. The repo contains code (CSS, JS, block definitions); DA contains page content. Block syntax: add a div with the block name as a CSS class (e.g. zip-hero, plan-cards). The EDS decoration engine picks it up automatically.

fstab.yaml

# fstab.yaml — tells EDS where to find the code repository mountpoints: /: type: github url: https://github.com/AdobeDrago/nrg branch: main

Plan-cards regex classification

The plan-cards block uses regex to classify each paragraph. If a paragraph matches multiple patterns, the first match wins (rate → term → tag → description). This means the order of authored paragraphs matters — put rate first, then term, then features, then description.

EDS escapes raw HTML in <p> tags

Gotcha. EDS escapes raw HTML inside <p> tags — interactive elements (inputs, buttons, toggles) must be built in block JS, not authored as HTML in DA. The zip-hero block builds its input, submit button, and Yes/No toggle entirely in JavaScript from text-only authored rows.

Code Sync app

AEM Code Sync (aem-code-sync, App ID 17488) deploys CSS/JS/blocks to the CDN. This is not aem-code-connector (the AI agent integration, which doesn't deploy). Make sure the correct app is configured in the Adobe Developer Console.
